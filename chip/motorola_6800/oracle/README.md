# Oracle fixtures — provenance

All fixtures were generated by the independent MC6800 oracle in
`ai_hw_engineer/design/motorola_6800` (never from the Rust core under
test) and committed so the tests are self-contained.

## isa/ — full-ISA vector replay

Generated 2026-10-26 by `design/motorola_6800/scripts/make_isa_vectors.py`
(an instruction-set simulator written from M68PRM(D) only). Deterministic
(LCG seed 0x6800): the directed program covers all 197 documented opcodes
in every addressing mode plus IRQ/NMI/SWI/WAI scenarios.

- `vectors.hex` — one (pc a b ix sp cc) record per opcode-fetch boundary,
  six four-digit hex fields per line; `ffff…` terminator last.
- `mem.hex` — initial 64K image (one hex byte per line).
- `gold_mem.hex` — oracle's final memory.
- `triggers.hex` — external interrupt events: `pc action delay`
  (0 = IRQ low, 1 = IRQ high, 2 = NMI pulse; delay in clocks after the
  fetch at pc).

The same files gate the SystemVerilog RTL (tb_top.sv), which passes.

## thirdparty/ — hakanrw/mc6800 programs

50 self-checking MC6800 test programs, MIT-licensed, from
https://github.com/hakanrw/mc6800 (vendored as `.asm` in
`ai_hw_engineer/design/motorola_6800/references/hakanrw_mc6800/`,
assembled by `design/motorola_6800/scripts/assemble_thirdparty.py`).

`<name>.oracle.txt` per test holds the image as non-zero spans, the
oracle's self-loop pc, the expected $2000-$20FF marker window, and the
SHA-256 of the full 64K image; `manifest.txt` lists the 50 names in run
order. Windows were computed by running the independent ISS over each
assembled image — the same windows the RTL checker compares against.
