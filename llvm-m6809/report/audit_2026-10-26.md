# Audit record — llvm-m6809, 2026-10-26

Stage-1 record for hevangel/ai_engineer#62 (America/Vancouver date).

## What exists now (this folder)

- `spec/audit_upstream.md` — the LLVM 6809 backend story is an abandoned
  LLVM 2.x-era SourceForge project (`llvm6809be`, never upstreamed);
  gcc6809 (GCC 4.3.6) and CMOC are actively-usable C compilers held up as
  ABI/codegen references, LWTOOLS 4.24 (2025-04-18) as the maintained
  assembler/linker and encoder cross-check; XRoar/MAME as machine
  emulators. No LLVM or Rust implementation can target the MC6809 today.
  All sources linked, checked 2026-10-26.
- `spec/compiler_profile.md` — exact-variant contract (plain MC6809; no
  6309/68HC11), the five-byte indexed-postbyte addressing set as the named
  qualification surface, D/X/Y/U/S register model, DP policy candidates,
  gcc6809-anchored ABI proposal, S-record/DECB/OS-9 packaging, vector map.
- `plans/implementation_plan.md` — M0–M4 staged plan on the
  llvm-i4004/i8008 route with the postbyte table as the named MC-layer
  work item.

## Independent behavior checks (fresh, this session)

The executor side of the future qualification chain was validated by
re-running the ai_hw_engineer MC6809 verification flow in the
`ai-hw-engineer:codex-java` container (Verilator), 2026-10-26:

- `design/motorola_6809/scripts/run_sim.sh`: **both third-party suites
  PASSED** — `6809_functional_test` (DEV_EXIT=0) and `6809_interrupt_test`
  (DEV_EXIT=0, 7,415 bus cycles), the hardware-validated reyco2000
  programs, on fresh builds.

This establishes that an independent, hardware-anchored machine oracle
exists and works today for the 6809 — the executor a future llvm-m6809
backend will be qualified against.

## What does NOT exist (explicit gaps)

- No backend code, no target JSON, no runtime, no tests in this repo: there
  is **no working Rust/LLVM compiler for the MC6809**, and none is claimed.
- No Rust program has been compiled for the 6809; no compiler output has
  been executed; no ROM budget measured.
- 6309/68HC11 supersets out of scope; 6800 is issue #61; 68k is #64.
