# Rust for llvm-i8086

The pinned rustc has no i8086 target, so `scripts/build_rust.sh` takes the msp430 route: rustc builds `core` and the crate for `msp430-none-elf` (`-Zbuild-std=core`, `panic=abort`, fat LTO), whose data layout equals `spec/abi.md` D1 for every alignment that matters, emits one LLVM IR module, and the script replaces its triple and data layout with ours, refuses what the backend lacks (floating point, i128, atomics, vectors), and runs `llc -mtriple=i8086`. `i8086-none.json` is for a rustc linked against our LLVM, which does not exist yet.

Programs: `tests/smoke/hello_rs` and `tests/smoke/stress_rs` (one source, run on the 8088 and natively on the host, texts compared) with the HAL in `system/ibm_pc/platform/hal` and `runtime/{crt0,hal}.s`. Tests: `system/ibm_pc/emulator/tests/i8086_rust.rs` (bare core always; original BIOS with `--ignored`).

`tests/smoke/irq_rs` takes over the timer and keyboard interrupts with handlers written in Rust: `extern "msp430-interrupt" fn` (feature `abi_msp430_interrupt`) is the `msp430_intrcc` calling convention, which llvm-i8086 compiles as an interrupt handler (`spec/abi.md` D5); `ibm_pc_hal::set_vector` installs it. It counts five timer ticks, reads six scan codes the test types, and prints them. The RTL and the Rust emulator show the same screen (`system/ibm_pc/emulator/oracle/boot/irq_rs.txt`, `tests/boot_oracle.rs`; the final registers are not compared because the timer interrupt does not fall on the same instruction in both).

Variadic functions and `byval` arguments compile (`spec/abi.md` D3a), so `core::fmt` machinery that uses them, and C-style APIs, work. Port I/O has no intrinsic: it is assembly in the HAL (`runtime/hal.s`) or inline `asm` with explicit register constraints (`tests/codegen/inlineasm.ll`).

Known limits: opt-level 0 is rejected (unoptimised `core` keeps floating point and i128 code that link-time optimisation would have removed), and the three `llc -O0` builds at opt-level 1 to 3 are too large for the 64 KiB tiny model (the matrix test skips them and says so). Everything else agrees with the host: `scripts/stress_matrix.sh` builds `stress_rs` at opt-level 1, 2, 3, `s`, `z` with `llc -O2` and `-O0`; seven of the ten run on the bare 8088 core and print the host's text. Finding this took two backend fixes: a displacement wider than 16 bits tripped an assertion when compiling `core`, and values pinned to the single-register class `GR16_BASE` could not be allocated (selection now makes a short-lived copy at each address use and `shouldCoalesce` refuses to join into the address classes).
