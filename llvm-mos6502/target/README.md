# `llvm-<chip>/target/` — backend target sources

This directory holds the LLVM target sources for a new-target backend, applied
onto a scratch copy of `external/llvm-project` by `scripts/apply_overlay.py`
(the submodule is never edited in place). Two layouts, by backend strategy:

## New experimental target (no existing backend — e.g. 4004, 8008)

```
target/
├── lib/Target/<Chip>/          mirrors llvm/lib/Target/<Chip>/ in the LLVM tree
│   ├── <Chip>.td, *.td          TableGen: registers, instr formats, encodings
│   ├── MCTargetDesc/            MC layer: AsmInfo, CodeEmitter, AsmBackend,
│   │                            ELFObjectWriter, InstPrinter, FixupKinds
│   ├── AsmParser/               assembly parser
│   ├── Disassembler/            MCDisassembler (bytes -> MCInst)
│   ├── TargetInfo/              target registration (getThe<Chip>Target)
│   ├── <Chip>TargetMachine.cpp  CodeGen entry (once past the MC-only milestone)
│   └── CMakeLists.txt           add_llvm_target + add_subdirectory(...) per dir
├── llvm-include/llvm/           headers installed into the LLVM tree, e.g.
│   └── BinaryFormat/ELFRelocs/<Chip>.def
└── patches/                     (optional) upstream core files a new target must
                                 touch (Triple.h/.cpp, ELF.h, ELFObjectFile.h,
                                 ELFDumper, ...). Prefer anchored, idempotent
                                 edits scripted in apply_overlay.py over raw
                                 patch files; use patches/ only for edits too
                                 large or too structural to anchor cleanly.
```

The overlay script, not this directory, owns the core-infra edits; everything a
`-gen-*` TableGen pass produces (`*GenInstrInfo.inc`, `*GenAsmWriter.inc`,
`*GenDisassemblerTables.inc`, …) is **generated into the build tree and never
committed** — it is regenerated by `scripts/build_llvm.sh` on every build.

## Backend built on another project (e.g. llvm-mos for the 6502 family)

```
target/
└── patches/                     ONLY. The backend already exists upstream
                                 (external/llvm-mos); you carry overlay/patch
                                 sets against it, not a full lib/Target/<Chip>/.
```

A `lib/Target/<Chip>/` tree here would duplicate code that already lives in the
base project; for those backends keep `patches/` alone and point
`apply_overlay.py` at the base checkout.

## Conventions

- Target sources are committed; build artifacts and the scratch LLVM tree are
  not (`.gitignore` covers `install/`, `build/`, the Docker build volume).
- One `CMakeLists.txt` per subdirectory; the top one calls `add_llvm_target`
  and `add_subdirectory(MCTargetDesc|TargetInfo|AsmParser|Disassembler)`.
  Adding a `Disassembler/` subdir makes CMake regenerate
  `llvm/Config/Disassemblers.def` at configure time, so a clean reconfigure
  (`CLEAN_OBJ=1`) is needed the first time one is added.
